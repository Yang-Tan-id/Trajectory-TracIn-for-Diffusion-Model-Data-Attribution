diffusion_jax_refined test overview
===================================

Run command
-----------

From the repository root:

  bash diffusion_jax_refined/tests/run_all_tests.sh

The runner prints a compact terminal summary and writes a detailed timestamped
log to:

  diffusion_jax_refined/tests/logs/test_YYYYmmdd_HHMMSS.log

The tests are intentionally lightweight: CPU-only, no GPU, no real checkpoint
loading, and no large CIFAR2 data. They should finish well under 15 minutes
(currently around a fraction of a second locally).


Test files
----------

1. test_algorithm_logic.py

   These are toy mathematical logic tests, not just config checks.

   They cover:

   - toy TracIn/influence scores should predict one-step LDS/query-loss
     improvement direction;
   - flipping the prediction sign should flip LDS correlation negative;
   - trajectory shards should merge to the same prediction as full scores;
   - DAS batched scoring should match unbatched scoring exactly;
   - endpoint MC objective batching should match explicit MC averaging;
   - duplicate score policies (max/sum/mean) should change predictions in the
     expected way.

   Purpose: catch future changes that silently break attribution/LDS math while
   still being fast enough for every commit.


2. test_paths_config.py

   These tests protect result-folder conventions.

   They cover:

   - attribution scores go under query_<query>/initial_seed_<seed>;
   - eval outputs go under query_<query>/initial_seed_<seed>;
   - different CIFAR2 queries map to distinct folders;
   - user-facing one-based ranges like 1-2000 map to zero-based internal indices
     like 0-1999.

   Purpose: prevent query/seed mixing and accidental overwrites.


3. test_score_indices.py

   These tests protect score-index bookkeeping.

   They cover:

   - one-based range parsing;
   - the five traj_tracin shards cover exactly 10,000 unique datapoints;
   - both score_indices.npy-style and score_indices.json-style metadata are
     accepted by the lightweight loader;
   - duplicate policies max/sum/mean are deterministic;
   - LDS kept indices are covered by the full score universe.

   Purpose: prevent off-by-one errors, missing datapoints, duplicate instability,
   and shard coverage bugs.


4. test_lds_eval_math.py

   These tests protect LDS evaluation math and output naming.

   They cover:

   - Spearman correlation sanity checks;
   - kept vs removed prediction subsets;
   - prediction sign handling;
   - prediction tags include subset/sign so output folders do not overwrite each
     other;
   - compact LDS model group names keep seed-range information without creating
     huge paths;
   - a fake LDS regression with aligned predicted/true values gives high
     correlation;
   - summary metadata records target_function, prediction_subset, and
     prediction_sign.

   Purpose: prevent LDS eval regressions and output-path collisions.


5. test_sample_validation.py

   These tests protect sampling input validation.

   They cover:

   - valid sample metadata passes;
   - prompt mismatch fails;
   - seed mismatch fails;
   - trajectory/time/final-state shape mismatch fails.

   Purpose: catch the common failure mode where attribution accidentally reads a
   sample from the wrong query or initial seed.


6. test_lds_model_config.py

   These tests protect reusable LDS model subset metadata.

   They cover:

   - k=5000 creates 5000 kept and 5000 excluded indices;
   - kept/excluded are disjoint and cover the 10,000-point universe;
   - k=8000 creates 8000 kept and 2000 excluded indices;
   - SAMPLE_MODEL_MODE, model training seed, and subset seed are separate folder
     levels;
   - configurable model training seed is recorded in metadata and checkpoint
     naming;
   - dataset percentage is recorded with the derived subset size.

   Purpose: prevent confusing LDS subset seed with actual diffusion model train
   seed, and protect fixed-k plus percentage-sized experiments.


7. test_script_layout_static.py

   These tests protect the refined script layout after moving TACC launchers
   into each dataset.

   They cover:

   - the top-level tacc script directory is absent;
   - every dataset has tacc/h100 and tacc/vista launchers;
   - every dataset exposes four train modes:
     prompted_solo, prompted_multi, unprompted_solo, and unprompted_multi;
   - every dataset has a scripts/script_0.sh selector for those train modes;
   - train scripts delegate to common/train_shell_lib.sh;
   - training launchers do not use QUERY, TRAIN_PROMPTS, TRAIN_MODEL_TAG, or
     prompt-specific model folders for dataset filtering/checkpoint identity;
   - dataset-local tacc script_0 launchers select TRAIN_MODE, GPU_IDS, and
     JAX_NUM_DEVICES before delegating to that dataset's script_0;
   - dataset and TACC datapoint-gradient launchers accept optional TRAIN_MODES,
     DATAPOINT_GRADIENT_MODES, and ALGORITHMS/ALGO values with comma or space
     separators;
   - dataset and TACC sample launchers accept SAMPLE_MODEL_MODE, EXPERIMENT_TAG,
     SAMPLE_SEEDS, and write data-attribution trajectories under
     result/<experiment>/sample/;
   - dataset and TACC sample+query-gradient launchers run sampling and
     02_query_gradient.py as one job, writing query gradients next to the sample
     seed folder;
   - score outputs are rooted by SAMPLE_MODEL_MODE and TRAIN_SEED before
     query/unprompted and initial seed;
   - LDS eval outputs are rooted by SAMPLE_MODEL_MODE before query/unprompted
     and initial seed;
   - CIFAR2/CIFAR10 LDS training scripts accept SAMPLE_MODEL_MODE,
     LDS_MODEL_TRAIN_SEED, LDS_M/LDS_NUM_SUBSETS, and either
     LDS_DATASET_PERCENTAGE or LDS_K/LDS_SUBSET_SIZE;
   - datapoint-gradient launchers write under
     model/<train_mode>/seed_<TRAIN_SEED>_train_gradient/<algorithm>/ instead of
     query attribution folders;
   - old algorithm-local run_attribution.py, run_training.py, run_eval.py, and
     script.sh entrypoints are absent after the three-stage split;
   - every dataset/algorithm-local script.sh calls the dataset-local refined
     scripts under ${ROOT}/scripts;
   - algorithm-local scripts no longer call stale absolute /scripts paths.

   Purpose: keep the refined workflow self-contained per dataset while we
   keep each dataset's launch layer next to its own result directory.


8. test_aggregate_lds_by_seed.py

   These tests run the per-seed aggregation logic on fake LDS result CSV files.

   They cover:

   - per_seed_summary.csv is written;
   - per_seed_summary.json is written with num_seeds, num_points, and LDS mean;
   - all_seed_points.csv is written;
   - per_seed_scatter_grid.svg is written;
   - all_points_scatter.svg is written.

   Purpose: make sure separate per-seed evals can be summarized into mean ± std
   tables and combined scatter overview figures without rerunning GPU eval.


9. test_attribution_code_contracts.py

   These tests protect high-level attribution-code contracts by checking the
   implementation source.

   They cover:

   - DAS currently saves squared-magnitude scores;
   - traj_tracin keeps trajectory_noise_squared_deviation as the default
     objective and also exposes normalized eps-deviation L1 / L2-squared
     query objectives for method probes;
   - non-default traj_tracin objectives write to distinct attribution folders;
   - DAS saves squared-magnitude scores while the Sherman-Morrison denominator
     remains an explicit opt-in option;
   - EndTracIn uses endpoint-anchored loss with MC samples;
   - CIFAR2 attribution/eval sample-count settings are pinned at 10 for MC /
     expectation samples;
   - CIFAR2, CIFAR10, and ArtBench attribution configs expose tunable GPU
     batch/chunk knobs such as TRAJ_SNAPSHOT_CHUNK_SIZE, DTRAK_BATCH_SIZE, and
     JOURNEY_BATCH_SIZE;
   - D-TRAK train features are computed with a batched jax.vmap helper instead
     of a Python loop over datapoints;
   - D-TRAK PASS1 caches phi_cache while building the Gram matrix, and PASS2
     reads Phi from that cache instead of calling train_phi_batch_fn a second
     time;
   - DAS, D-TRAK, EndTracIn, TrajTracIn, and JourneyTRAK each expose a
     method-specific stages.py facade for train gradients/features, query
     gradients/features, and score calculation.

   Purpose: make intentional algorithm-definition changes visible. If one of
   these fails after an intentional method change, update both the code and this
   test/overview together.


What this suite does not do
---------------------------

- It does not train diffusion models.
- It does not load real H100 checkpoints.
- It does not run JAX/GPU kernels.
- It does not verify final CIFAR2 scientific quality.

Instead, it is a fast regression suite for logic, path conventions, metadata,
score indexing, sharding, LDS math, and script-layout safety.
